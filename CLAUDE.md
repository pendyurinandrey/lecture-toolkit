Правила разработки lecture-toolkit — локального офлайн-набора для записей лекций
(нарезка/склейка видео, распознавание речи, определение говорящих, GUI `pipeline_ui.py`).

## Правила для `common/`

Сюда попадает только то, что нужно двум и более пакетам (или заведомо будет нужно);
остальное живёт в пакете-владельце.

1. Файл называется по тому, что в нём лежит, а не по фиче, которой он понадобился первой.
2. Всё, что запускает ffmpeg/ffprobe, — в `common/ffmpeg.py` (`run_ffmpeg` для нарезки/склейки/конвертации,
   отдельные функции для длительности, пауз, ключевых кадров). Ошибки — только `FFmpegError`;
   вызывающий код не разбирает `CalledProcessError`/`FileNotFoundError`. Свои `subprocess.run(["ffmpeg", ...])`
   в других модулях не писать.
3. Чистая логика над интервалами и списками времён (без запуска процессов и чтения файлов) —
   в `common/intervals.py`.
4. Обработка текста — в `common/filler_words.py`.
5. Новый файл в `common/` — только если функциональность не подходит ни к одному существующему
   по смыслу, и в ответе объяснить почему. Не заводить `utils.py`, `helpers.py`, `media_tools.py`.
6. Если место для новой функции неочевидно — сначала обсудить, потом писать.

## Тяжёлое — в отдельных процессах

GUI-процесс (`pipeline_ui.py`) не считает и не держит модели. Диаризация и GigaAM запускаются
отдельными процессами (`python -m ...` из `transcribe_lecture._run_module`): память
освобождается после каждого этапа. Поэтому `diarization/__init__.py`, `speaker_labels.py` и
верхний уровень `diarize_pyannote.py` не импортируют `pyannote` (а также `torch`/`numpy`) —
только внутри функций. `torch` в GUI-процессе уже есть через `import gigaam`, это допустимо.

## Подводные камни

- **macOS и `DYLD_*`.** Системные утилиты (`nohup` и др. из `/usr/bin`) вычищают `DYLD_FALLBACK_LIBRARY_PATH`.
  Для фонового запуска использовать `subprocess.Popen(..., start_new_session=True, env=...)`, не `nohup`.
  Переменная нужна, когда системный ffmpeg версии 9+ (torchcodec поддерживает 4–8), см. FAQ в README.
- **Editable-установка.** `pip install -e .` запоминает список пакетов на момент установки; новый
  пакет нужно добавить в `include` в `pyproject.toml` и переустановить. Дочерние процессы получают
  корень репозитория в `PYTHONPATH` (`_run_module`), поэтому запуск из любой папки работает.
- **Два venv.** `speech_to_text_whisper` и GigaAM требуют несовместимые версии `torch`;
  `pipeline_ui` работает в корневом venv только с GigaAM.
- **Gated-модели Hugging Face.** Новую модель с условиями использования проверять в кэше ДО долгой
  работы (`check_model_available`, `local_files_only=True`) и выдавать инструкцию; описать в FAQ README.
- **Долгие прогоны.** Полная обработка многочасовой записи (диаризация + GigaAM) занимает больше
  часа и нагружает память — запускать только по просьбе пользователя.

## Тесты

```shell
pip3 install -e ".[dev]"
python3 -m pytest
```

Перед завершением работы запускать `python3 -m pytest` (не голый `pytest`: он может взяться из системного
Python без GigaAM, и часть тестов молча пропустится) — из активированного venv или как `./venv/bin/python -m pytest`. Тесты покрывают чистую логику и не требуют
медиафайлов, ffmpeg и нейросетей (обёртки ffmpeg проверяются с подменой `subprocess.run`).
Дерево тестов повторяет дерево кода: `tests/<пакет>/test_<модуль>.py`
(например, `common/ffmpeg.py` → `tests/common/test_ffmpeg.py`). `__init__.py` в `tests/` не нужны:
в `pyproject.toml` включён `--import-mode=importlib`, поэтому одинаковые имена файлов в разных
папках допустимы, а `tests/common` не затеняет пакет `common`.
CI: `.github/workflows/tests.yml` гоняет `pytest` на каждый push (Python 3.10 и 3.12), ставится только
`pytest` — без GigaAM/torch, поэтому `tests/speech_to_text_gigaam` там пропускается (`skipped`), это ожидаемо.
Новую чистую логику — с тестом. Не привязывать тесты к файлам пользователя (например, из `~/Movies`).
