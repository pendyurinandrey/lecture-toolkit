# lecture-toolkit

Набор инструментов для работы с записями лекций: нарезка/склейка видео и локальная транскрибация речи в текст — без онлайн-сервисов.

Полный конвейер состоит из следующих шагов:

1. **fork_join** — вырезать нужные фрагменты из исходных видео (Zoom-записей и т.п.), склеить их в одну лекцию и извлечь звуковую дорожку в M4A.
2. **speech_to_text_gigaam** — распознать эту дорожку в текст (два независимых движка на выбор, см. ниже) и получить читаемый текст с пунктуацией, без слов-паразитов.

## pipeline_ui.py — графический интерфейс для полного конвейера

### Что нужно сделать перед первым запуском

* Проверить, что на компьютере установлен Python 3 (тестирование проводилось на версии 3.10)
* Создать Virtual Environment и установить зависимости

```shell
python3 -m venv venv
source venv/bin/activate
pip3 install -r requirements.txt
pip3 install -e .
```

* Проверить, что локально установлен `ffmpeg`. Версия должна быть между `4.х.х` и `8.x.x` включительно. См. [Что делать если у меня ffmpeg 9?](#что-делать-если-версия-ffmpeg-9), если установлена версия новее

```shell
ffmpeg -version
```

* Создать аккаунт Hugging Face и установить токен (см. [Как получить и установить Hugging Face токен?](#как-получить-и-установить-hugging-face-токен))

### Как запустить и использовать

В терминале, где ранее была активирована Virtual Environment, выполнить:

```shell
python3 pipeline_ui.py
```

В окне: собираете список видео/фрагментов (дерево файлов/фрагментов), указываете пути для видео/аудио/транскрипции, при необходимости отключаете чекбоксы "Выполнить распознавание речи (GigaAM)", "Убирать слова-паразиты" или "Не давать компьютеру уснуть во время обработки" — и жмёте "Запустить". Лог и время выполнения каждого шага отображаются в окне программы.

## Описание модулей

### fork_join

Нарезает фрагменты из MP4-файлов по конфигурации в JSON, склеивает их в единый MP4 и дополнительно сохраняет звуковую дорожку итогового файла в M4A — оба шага копированием потоков (без перекодирования, без потери качества: звук в исходном MP4 уже сжат AAC, и повторное сжатие в другой lossy-формат вроде MP3 давало бы вторую генерацию потерь без необходимости).

#### Использование

Через командную строку:

```bash
python3 -m fork_join.fork_join path/to/config.json
```

Отдельного графического интерфейса у `fork_join` нет — редактор конфигурации (дерево файлов/фрагментов) встроен в `pipeline_ui.py` (см. выше); чтобы собрать только видео/аудио без распознавания речи, просто снимите чекбокс "Выполнить распознавание речи (GigaAM)".

#### Формат конфигурации

```json
{
	"segments": [ {
		"path": "/Users/andreip/Movies/2026-09-03 18-00-15.mp4",
		"fragments": [
			{
				"start": "00:01:11",
				"end": "00:55:05"
			}
		]
	},
	{
		"path": "/Users/andreip/Movies/2026-09-03 19-04-17.mp4",
		"fragments": [
			{
				"start": "00:01:10",
				"end": "00:32:10"
			},
			{
				"start": "00:44:00",
				"end": "02:06:40"
			}
		]
	}
	],
	"output": {
		"videoPath": "/Users/andreip/Movies/Общая_Психология_03.09.2026.mp4",
		"audioPath": "/Users/andreip/Movies/Общая_Психология_03.09.2026.m4a"
	}
}
```

**Описание формата:**

- `segments` — массив объектов, содержащий от 1 до 20 объектов. Каждый объект
  представляет информацию об одном видео файле в формате MP4 (AAC, H.264).
  Каждый объект массива `segments` содержит:
  - `path` — полный путь до видео файла
  - `fragments` — массив от 1 до 20 объектов. Поле `start` объекта указывает
    время начала фрагмента в формате `HH:mm:ss`, поле `end` — время окончания
    фрагмента в формате `HH:mm:ss`
- `output.videoPath` — полный путь к выходному видео файлу в формате MP4
- `output.audioPath` — полный путь к выходному аудио файлу в формате M4A

### speech_to_text_whisper

Локальная транскрибация лекции в текст: распознавание речи (`faster-whisper`,
CPU, beam search + VAD) и последующее восстановление пунктуации/регистра
(`kontur-ai/sbert_punc_case_ru`) с удалением слов-паразитов. Модели скачиваются
один раз и кэшируются в `~/.cache/huggingface/hub`.

#### Установка (отдельная от корневого `requirements.txt`)

```bash
cd speech_to_text_whisper
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cd ..
./speech_to_text_whisper/venv/bin/pip install -e .
```

Своя отдельная виртуальная среда нужна из-за несовместимой версии `torch`
(см. [Какой движок распознавания речи выбрать](#какой-движок-распознавания-речи-выбрать) ниже).

#### Использование

Состоит из двух шагов, второй можно перезапускать отдельно (не требует повторного распознавания речи):

##### 1. Распознавание речи

```bash
python3 -m speech_to_text_whisper.transcribe lecture.m4a --save-json
```

Создаёт `lecture.txt` (черновой текст с таймкодами) и `lecture.json` (сырые
сегменты с таймкодами и метриками уверенности распознавания — нужен для шага 2).

Основные флаги:

| Флаг                         | По умолчанию   | Назначение                                                                                                               |
|------------------------------|----------------|--------------------------------------------------------------------------------------------------------------------------|
| `--model`                    | `large-v3`     | Размер модели faster-whisper                                                                                             |
| `--language`                 | `ru`           | Язык распознавания                                                                                                       |
| `--beam-size`                | `5`            | Ширина beam search (больше — точнее, но медленнее)                                                                       |
| `--initial-prompt`           | нет            | Подсказка с ожидаемыми именами/терминами лекции (например: `"Вундт, интроспекция"`) — помогает распознавать редкие слова |
| `--no-flag-uncertain`        | флаги включены | Отключить пометку `[?]` у абзацев с низкой уверенностью распознавания                                                    |
| `--confidence-threshold`     | `-0.5`         | Порог `avg_logprob`, ниже которого сегмент считается ненадёжным                                                          |
| `--no-speech-threshold-flag` | `0.6`          | Порог `no_speech_prob`, выше которого сегмент считается ненадёжным                                                       |

##### 2. Восстановление пунктуации

```bash
python3 -m speech_to_text_whisper.restore_punctuation lecture.json
```

Создаёт `lecture_punctuated.txt` — читаемый текст с восстановленной
пунктуацией/регистром, без слов-паразитов, с абзацами, разбитыми строго по
границе предложения (никогда не обрывается посередине фразы), и с таймкодом
в начале каждого абзаца.

Основные флаги:

| Флаг                                                                            | По умолчанию       | Назначение                                                                                                          |
|---------------------------------------------------------------------------------|--------------------|---------------------------------------------------------------------------------------------------------------------|
| `--keep-fillers`                                                                | паразиты удаляются | Не удалять слова-паразиты (вот, ну и т.п.)                                                                          |
| `--no-flag-uncertain` / `--confidence-threshold` / `--no-speech-threshold-flag` | как в шаге 1       | То же самое, но применяется отдельно на этом шаге — можно подобрать порог постфактум, не перезапуская распознавание |

**Известное ограничение:** метки `[?]` ловят места, где сама модель распознавания
не уверена в своём выводе, но не ловят случаи, когда модель "уверенно"
пропустила или подменила слово, сохранив при этом гладкую, правдоподобную
фразу. Для таких мест пока нет автоматической проверки — при сомнении в
конкретной фразе стоит сверить её с оригинальным аудио.

### speech_to_text_gigaam

Локальная транскрибация через [GigaAM-v3](https://github.com/salute-developers/GigaAM)
(`v3_e2e_rnnt`) — модель уже сама расставляет пунктуацию и регистр, отдельный
шаг восстановления пунктуации не нужен.

#### Установка (отдельная от корневого `requirements.txt`)

```bash
cd speech_to_text_gigaam
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cd ..
./speech_to_text_gigaam/venv/bin/pip install -e .
```

Дополнительно нужны (проверяются автоматически при запуске — см. ниже):

- **Аккаунт Hugging Face + токен** (бесплатно) — см. [Как получить и установить Hugging Face токен?](#как-получить-и-установить-hugging-face-токен)
- **ffmpeg версии 4-8** — если ваш системный `ffmpeg` новее, при запуске
  выведется понятная ошибка; см. [Что делать если версия ffmpeg 9+?](#что-делать-если-версия-ffmpeg-9)

#### Использование

```bash
./venv/bin/python -m speech_to_text_gigaam.transcribe_longform_chunked lecture.m4a --output lecture.gigaam.txt
```

Скрипт сам:
1. находит паузы в речи через `ffmpeg silencedetect` (лёгкий, не ML) и режет
   аудио на куски ~30 минут строго по этим паузам — никогда не разрезает
   слово посередине;
2. обрабатывает каждый кусок **отдельным процессом** — GigaAM/pyannote на
   многочасовых файлах непредсказуемо наращивают потребление памяти вплоть
   до исчерпания swap, разбивка на куски с независимыми процессами это
   обходит;
3. убирает слова-паразиты (аналогично `speech_to_text_whisper`, но с учётом
   того, что слова уже несут пунктуацию — при удалении паразита его знаки
   препинания не теряются, а переносятся на соседние слова);
4. перегруппировывает результат в абзацы строго по границе предложения
   (`.`, `?` или `!`) и склеивает всё в один файл с таймкодами.

Основные флаги:

| Флаг              | По умолчанию         | Назначение                    |
|-------------------|----------------------|-------------------------------|
| `--chunk-minutes` | `30`                 | Целевая длина куска в минутах |
| `--keep-fillers`  | паразиты удаляются   | Не удалять слова-паразиты     |
| `--output`        | `<audio>.gigaam.txt` | Путь к итоговому файлу        |

Есть также `transcribe_longform.py` — обрабатывает файл целиком одним
процессом (без нарезки и без удаления паразитов), используется внутри
`transcribe_longform_chunked.py` как воркер на один кусок; для файлов
короче ~40-60 минут можно использовать напрямую.

## Какой движок распознавания речи выбрать

> [!NOTE]
> pipeline_ui поддерживает только GigaAM-v3.

|                                       | speech_to_text_whisper                                                                                          | speech_to_text_gigaam                                      |
|---------------------------------------|-----------------------------------------------------------------------------------------------------------------|------------------------------------------------------------|
| Движок                                | faster-whisper (large-v3)                                                                                       | GigaAM-v3 (Сбер)                                           |
| Точность на русском                   | Хорошая                                                                                                         | Заметно лучше на именах/терминах                           |
| Пунктуация                            | Отдельный шаг, модель `kontur-ai/sbert_punc_case_ru`                                                            | Встроена в саму ASR-модель                                 |
| Скорость (2.5-3ч лекция, M1 Pro, CPU) | ~80-95 мин                                                                                                      | ~50-90 мин, зависит от длины кусков                        |
| Внешние аккаунты                      | Не нужны                                                                                                        | Нужен бесплатный аккаунт Hugging Face + токен (см. модуль) |
| Статус                                | Сохранён, т.к. может пригодиться, например, если нужно будет распознавать смесь из русского и английского языка | Основной, обкатанный пайплайн                              |

Модули независимы и **используют разные, несовместимые версии `torch`**
(GigaAM тянет за собой более старый `torch` из-за зависимости от pyannote) —
поэтому у каждого своя отдельная виртуальная среда, объединить их в один
venv не получится.

## FAQ

### Что делать если версия ffmpeg 9+?

Касается только `speech_to_text_gigaam` (и, соответственно, шага
распознавания речи в `pipeline_ui.py`): `torchcodec`, через который
`pyannote.audio` внутри GigaAM читает аудио, поддерживает только FFmpeg
версий **4-8**. Если системный `ffmpeg -version` показывает 9 или новее,
нужно установить совместимую версию **рядом** с системной (не заменяя её —
она может быть нужна другим программам) и указать GigaAM путь к ней через
переменную окружения — сам системный `ffmpeg` при этом не трогаем.

Проще и надёжнее всего это сделать через изолированное conda-окружение: в
отличие от простого скачивания отдельного бинарника `ffmpeg`, conda-forge
даёт полноценные динамические библиотеки (`.dylib`/`.so`/`.dll`), которые и
нужны `torchcodec` — а не только сам исполняемый файл.

**1. Установить Miniconda (один раз, если ещё не установлена)**

Скачать и установить с [docs.conda.io/en/latest/miniconda.html](https://docs.conda.io/en/latest/miniconda.html)
— инструкции на сайте отдельные для Windows/macOS/Linux.

**2. Создать окружение с закреплённой версией ffmpeg**

Команда одинаковая на всех ОС (выполняется в обычном терминале/PowerShell,
не в venv проекта):

```shell
conda create -n ffmpeg8 -c conda-forge "ffmpeg<9" -y
```

Это отдельное, полностью изолированное окружение — системный `ffmpeg`
никак не затрагивается.

**3. Указать путь к библиотекам переменной окружения**

Переменная и расположение библиотек внутри окружения зависят от ОС
(`<conda>` — папка, куда была установлена Miniconda, обычно
`~/miniconda3` на macOS/Linux или `%USERPROFILE%\miniconda3` на Windows):

| ОС      | Переменная                                                                                  | Путь                               | Команда (в терминале, после активации venv проекта)                                           |
|---------|---------------------------------------------------------------------------------------------|------------------------------------|-----------------------------------------------------------------------------------------------|
| macOS   | `DYLD_FALLBACK_LIBRARY_PATH`                                                                | `<conda>/envs/ffmpeg8/lib`         | `export DYLD_FALLBACK_LIBRARY_PATH="$HOME/miniconda3/envs/ffmpeg8/lib"`                       |
| Linux   | `LD_LIBRARY_PATH`                                                                           | `<conda>/envs/ffmpeg8/lib`         | `export LD_LIBRARY_PATH="$HOME/miniconda3/envs/ffmpeg8/lib"`                                  |
| Windows | `PATH` (отдельной переменной нет — Windows ищет библиотеки там же, где и исполняемые файлы) | `<conda>\envs\ffmpeg8\Library\bin` | PowerShell: `$env:PATH = "$env:USERPROFILE\miniconda3\envs\ffmpeg8\Library\bin;" + $env:PATH` |

**4. Чтобы переменная подхватывалась автоматически при активации venv**

Каждый venv, созданный командой `python3 -m venv venv`, генерирует скрипт
активации — в него можно один раз дописать нужный `export`/`set`, и дальше
он будет применяться автоматически при каждом `source venv/bin/activate`:

```shell
# macOS — дописать в конец venv/bin/activate:
echo 'export DYLD_FALLBACK_LIBRARY_PATH="'"$HOME"'/miniconda3/envs/ffmpeg8/lib"' >> venv/bin/activate

# Linux — дописать в конец venv/bin/activate:
echo 'export LD_LIBRARY_PATH="'"$HOME"'/miniconda3/envs/ffmpeg8/lib"' >> venv/bin/activate
```

```powershell
# Windows (PowerShell) — дописать в конец venv\Scripts\Activate.ps1:
Add-Content venv\Scripts\Activate.ps1 '$env:PATH = "' + $env:USERPROFILE + '\miniconda3\envs\ffmpeg8\Library\bin;" + $env:PATH'
```

Важно: это дописывается в файл конкретного, уже созданного venv — если
venv пересоздать (`rm -rf venv && python3 -m venv venv`), строку нужно
будет добавить заново.

### Как получить и установить Hugging Face токен?

Нужен для скачивания gated-модели `pyannote/segmentation-3.0`, которую
GigaAM использует для нарезки длинного аудио на паузах речи.

1. Зарегистрироваться (бесплатно) на [huggingface.co/join](https://huggingface.co/join)
2. Открыть страницу модели [huggingface.co/pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0), войти под своим аккаунтом и принять условия использования (кнопка вида "Agree and access repository" на странице модели) — без этого шага скачивание модели будет падать с ошибкой доступа, даже если токен верный
3. Создать токен: [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) → "New token" → тип **Read** достаточно → скопировать токен (он показывается только один раз)
4. В терминале, где активирован venv проекта, выполнить `hf auth login` и вставить токен — он закэшируется локально (`~/.cache/huggingface/token`) и дальше будет подхватываться автоматически, не нужно ничего указывать в переменных окружения при каждом запуске
5. Альтернатива шагу 4 (если не хочется полагаться на локальный кэш) — задать токен явно переменной окружения `HF_TOKEN` перед запуском
